## WHAT WE ARE BUILDING (one line)
A Chrome extension "Friday" that reads the screen with a local in-browser AI,
redacts private data on-device, and acts on the page by voice or text — with
nothing sensitive ever leaving the machine.

## LOCKED DESIGN DECISIONS (do not change without updating this file)
- **DOM for control, vision for understanding.** Clicks/typing target real DOM +
  accessibility-tree elements (near-100% accuracy). Vision is only for screen
  understanding + PII detection.
- **On-device core = DOM + a11y + BlazeFace + Tesseract.js.** Millisecond-scale,
  no local VLM on the critical path. (Gate 0.7 confirmed the in-browser VLM is
  functionally correct but ~100× too slow on typical Intel-iGPU/CPU hardware
  for live use.)
- **Reasoning / screen-understanding = BYOK cloud** (Gemini Flash / OpenAI /
  Groq) via the **Brain Router**. Redaction ALWAYS runs on-device BEFORE any
  API call — the privacy boundary sits before the wire, not after.
- **Local in-browser VLM = OPTIONAL, off-by-default fallback** for strong-GPU
  users. Stays in the repo (popup Test AI + Run on sample) but is not on the
  primary path. No further performance chasing.
- **Fully in-browser, zero user setup** for the on-device core: DOM/a11y is
  free, detectors download once and cache. BYOK requires the user's own key,
  stored in `chrome.storage.local`.
- **Privacy boundary is absolute:** redaction runs on-device BEFORE any network
  or tool call.
- Chrome first. One flawless demo over many half-working features.

## STACK
Manifest V3 · JavaScript/TypeScript · Transformers.js + WebGPU · BlazeFace ·
Tesseract.js · Canvas API · content script (DOM control) · Web Speech API ·
BYOK (Gemini/OpenAI/Groq) · MCP client (stretch) · chrome.storage.local

## UNIQUE FEATURES (beyond the problem statement)
1. Voice-first agentic control ("Hey Friday").
2. Privacy receipt — shows exactly what was redacted, live.
3. Brain Router — local for speed/privacy, BYOK for hard tasks.
4. MCP connections — act across apps, PII redacted first.
5. Learns private items — mark once, always redacted.

- 2026-09-10 — 2.4 done: `src/redact.js` — Canvas-based on-device redactor. `collectRegions({dom, faces, ocr, viewport, imageWidth, imageHeight, pad})` normalises hits from all three detectors into a single `[{bbox, kind, source}]` list, handling the **coordinate-space mismatch** cleanly: DOM bboxes come from `getBoundingClientRect()` in CSS pixels, but `chrome.tabs.captureVisibleTab` returns a device-pixel image, so we compute `sx = imageWidth/viewport.width, sy = imageHeight/viewport.height` once and scale DOM boxes by it. Face + OCR bboxes are already in image pixels and pass through untouched. Faces get extra 12-16 px of pad since BlazeFace's tight box crops ears/hair. `expand()` handles the pad + clamps to zero. `redactImage({imageSource, regions, mode, blurPx})` decodes the source (accepts HTMLImageElement / HTMLCanvasElement / ImageBitmap / URL / dataURL), draws it once into a canvas at natural dimensions, then paints over each region via `applyMask()`. Three modes: `MASK` (solid black `fillRect` — fastest, strongest signal), `BLUR` (default, `ctx.filter = "blur(Npx)"` inside a `ctx.clip()` rect — smooth gaussian localised to the region), `MOSAIC` (downscale to a tiny temp canvas then upscale with `imageSmoothingEnabled=false` — pixelates for extra "clearly redacted" affordance). All three finish in a handful of ms even on 2880×1800 screenshots because we only redraw within clipped regions. Returns `{dataUrl, width, height, regionsApplied, regionsGiven, redactMs}`. Popup gained a "Redact" button: captures the screen (or reuses `lastCapture`), fires BlazeFace + Tesseract in **parallel** via `Promise.all` (unrelated work, no reason to serialise), combines all three detector outputs through `collectRegions`, applies `BLUR` at 22 px, and swaps the preview image to the redacted version. `lastCapture` (full CAPTURE_TAB payload — includes `pii`, `viewport`, `elements`) is now stashed on `onCapture` so redact can pull DOM regions without re-hitting the tab. Logs `[redact] faces=N ocr.words=M ocr.pii=K`, `[redact] regions=T (dom=… faces=… ocr=…)`, and `[redact] applied=A/G redactMs=… totalMs=…` — cleanly instruments each pipe. - 2026-09-10 — 2.1 done: `src/pii.js` — pure detector (no DOM access, safe to import in the service worker) that operates on the structured element list content.js already produces.
